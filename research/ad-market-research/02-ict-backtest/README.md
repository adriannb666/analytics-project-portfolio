# 02 · 把 ICT 策略写成代码，两年 BTC 回测 473 笔

2026-11-09 · BTCUSDT 15 分钟 · 2024-11-09 ~ 2026-11-08 · 70,080 根 K 线

## 规则（以做多为例，做空对称）

1. **扫流动性**：15m 摆动低点（左右各 5 根），4 天内形成；被刺破后 4 根 K 线内收盘收回；刺破深度 ≤ 1%
2. **位置过滤**：扫点在过去 5 天高低区间的下半部分（折价区）
3. **结构转变**：扫点后 6 小时内，收盘站上扫点后第一个反弹高点（若下跌途中最后一个反弹高点更低，则以它为准）；期间创新低则作废
4. **FVG 入场**：突破过程中最近的 FVG（缺口 ≥ 0.03%），上沿挂限价单；6 小时内不回踩或先碰到止盈位则撤单
5. **离场**：止损在扫点下方 0.05%，止盈 2R，最长持仓 24 小时
6. **手续费**：挂单 0.02%，止损/超时 0.05%；同一根 K 线同时碰到止损和止盈时按止损算

## 结果

| 指标 | 基础版 |
| --- | --- |
| 交易笔数 | 473（多 236 / 空 237） |
| 胜率 | 35.3% |
| 平均每笔（扣费前 / 扣费后） | −0.019R / −0.121R |
| 累计（扣费后） | −57.2R |
| 最大回撤 | 74.8R |
| 盈亏因子 | 0.82 |

12 种参数变体扣费后全部为负，最好的是「止盈 1R」：−0.056R。

**样本内 / 样本外**：用第一年（2024-11-09 ~ 2025-11-08）找出三条过滤：只做工作日、避开亚洲盘（美东 19–02 点）、止损距离 ≥ 0.5%。

| | 不过滤 | 加过滤 |
| --- | --- | --- |
| 第一年 | 234 笔，−0.206R | 110 笔，+0.034R |
| 第二年 | 239 笔，−0.038R | 109 笔，+0.153R（标准误约 ±0.13R，不显著） |

**随机游走对照**（发布后补充）：把同一套规则放到 6 组随机生成的价格数据上跑，扣费前平均每笔在 −0.13R 到 +0.08R 之间。真实数据的 −0.019R 落在这个范围中间，也就是说，这套规则在真实 BTC 上的表现和在随机数据上没有区别。

## 文件

- `backtest.mjs`：回测引擎（下载数据 → 跑全部变体 → 输出 `results.json` 和 `trades.csv`）
- `btdata.py`：画图用的资金曲线、月度收益和示例交易数据
- `plot_bt.py`：生成 `figures/` 里的 10 张图（示例赢单那张会用到 `../01-ict-complete-trade/data.py`）

```bash
node backtest.mjs
python3 plot_bt.py
```

## 局限

只测了一个品种、一个周期；没算滑点和资金费率；多空分开跑，极少数情况下会同时持仓；过滤条件是在看过全部数据的分组结果之后才定的，所以样本外检验不完全干净。
